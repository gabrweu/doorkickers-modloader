Door Kickers 2 - Native Mod Loader  v@VERSION@
==============================================

The Native Mod Loader lets Door Kickers 2 run mods that contain code (DLLs), such as Free Camera on the Steam
Workshop. On its own it changes nothing in the game.

Built for Door Kickers 2 @GAMEVERSION@. The loader finds the game's code by name, so game updates usually don't
break it. If an update removes something the loader or a mod needs, only that part stays off; the game runs normally.


INSTALL
-------
1. Close the game.
2. In Steam, right-click Door Kickers 2 > Manage > Browse local files. That opens the game folder
   (the one with DoorKickers2.exe).
3. Copy dk2ml.dll and dbghelp.dll from this download into that folder. dk2ml.dll is the loader; dbghelp.dll is a
   small stub that the game loads by that name, and it starts dk2ml.dll.

That's it. Now subscribe to native mods on the Steam Workshop and enable them in the game's Mods menu, as you
would any other mod. Each one can be turned on or off there on its own.

The game applies Mods menu changes without restarting, but code can only load when the game starts:
  - A native mod you disable is switched off right away (its code stays in memory, doing nothing, until you quit).
  - A native mod you enable starts working the next time you start the game.
The "Native mods" button shows a "!" while a change waits for a restart.

The main menu gets a "Native mods" button (bottom right, above "Send Feedback"). Its screen shows which of your
enabled mods contain native code and whether it loaded, opens its Workshop page and folders, and holds each mod's
settings.


THE PERMISSION PROMPT
---------------------
Native mods can do anything on your PC, like any program you install. So when the game starts and Workshop mods with
code are new or have been updated since you last answered, the loader asks you once (a Windows dialog), listing
them by name and Workshop item number:
  - Yes  loads those versions of their code.
  - No   doesn't load their code (the rest of each mod still loads).
You're asked again whenever a mod's code changes, for example after a Workshop update. Only say Yes to mods from
authors you trust. The names in the dialog come from the mods themselves; their Workshop pages tell you who made them.

Your answers are kept in dk2ml.ini in the game folder (created on the first start), under [workshop], one line per
mod. Delete a mod's line to be asked again at the next start. Mods you copied into the mods folder yourself load
without asking.


IF SOMETHING GOES WRONG
-----------------------
  - If a native mod keeps the game from starting, set enabled=0 under [loader] in dk2ml.ini (game folder): the
    game starts without native mods. Then disable the mod in the Mods menu and set enabled=1 again.
  - When the game crashes, the loader writes a crash report, dk2ml-crash-<date>-<time>.log, in the game folder
    (the 10 newest are kept). It says what crashed, which mods' code was involved, and where. Send it, with
    dk2ml.prev.log, to the author of the mod it names.
  - If a native mod crashes while you play, the loader usually catches it, switches that mod off for the rest of
    the session, and the game carries on. Its page on the Native mods screen says so. Tell its author, and include
    dk2ml.log.
  - If two native mods misbehave together: many mods can run at once, but two can still want different things from
    the same part of the game. Try them one at a time to find the pair. Their order in the Mods menu decides which
    one runs first, so changing it can change the result. The Native mods screen shows the conflicts the loader can
    see (shared files, the same hotkey), and dk2ml.log lists the game functions several mods hook. Report the pair
    to both authors.


UNINSTALL
---------
Delete dk2ml.dll and dbghelp.dll from the game folder (and dk2ml.ini and dk2ml.log if you like). The game is back to normal.
Native mods' settings are in %LOCALAPPDATA%\KillHouseGames\DoorKickers2\dk2ml.


TROUBLESHOOTING
---------------
Everything the loader does is written to dk2ml.log in the game folder; the session before is kept as dk2ml.prev.log
(after a crash, that's the one to send). Include it when reporting a problem.
  - "symbols unavailable"   DoorKickers2.pdb is missing or doesn't match the game; verify the game files in Steam
  - "declined"              you answered No for that mod; delete its line in dk2ml.ini to be asked again
  - "dk2ml.dll did not load"  copy dk2ml.dll from this download next to dbghelp.dll
  - to turn the loader off without deleting it, set enabled=0 in dk2ml.ini
Some antivirus programs distrust DLLs that load into games. The full source code is public, and the SHA-256 hashes of
dk2ml.dll and dbghelp.dll are listed on the release page.


FOR MODDERS
-----------
The loader loads any 64-bit DLL in an enabled mod's "native" folder (or the game folder's "mods_native" folder)
that exports DK2ML_PluginInit. Game functions, globals, struct fields and enums are looked up by name from the
DoorKickers2.pdb the game ships with. Everything you need is a separate download on the release page,
DK2-NativeModTemplate-v@VERSION@.zip: a plugin project that builds where you unzip it.
  - README.md, src\, mod\, *.ps1   CMake, an example plugin, the mod folder, build/install/package scripts
  - docs\cookbook.md     recipes (game state, calling and hooking game functions, hotkeys, settings, GUI, ImGui) and pitfalls
  - tools\symtest.exe    explores the game's symbols:  symtest.exe "<game folder>" --find "GameClient::*"
                         (also --types "*Camera*", --type Camera, --enum GameClient::eCGameState)
                         and dry-runs your plugin:      symtest.exe "<game folder>" <your plugin.dll>
                         A dry run must print "plugin init returned 0" and no PROBLEM lines (exit code 0).
  - dk2ml\dk2ml.h        the C API, dk2ml.hpp the optional C++ layer
  - tools\disasm.ps1     disassembly with names (optional, needs LLVM)
